# 05 · 测试与验收规范

> **"做完了"的定义是：三层验证都跑过，并且日志里写下来了。**
> 没跑验证就说完成 = 没完成。

---

## 一、为什么这个项目必须自测

纯静态前端没有编译期检查。一个元素 id 写错（HTML 写 `btn-skip`、JS 查 `#btnSkip`），
就会让整条流程静默中断——**页面看起来还在正常运转，只是点了没反应**。

本项目真实发生过这件事，直到把全流程自动跑了一遍才发现。所以：

> **每一次改动，无论多小，都必须跑验证。**

---

## 二、三层验证

### 第一层 · 静态检查（秒级，每次改完必跑）

```bash
python3 tools/check-ids.py
```

做两件事：
1. 用 `node --check` 检查三个 JS 文件的语法
2. **交叉核对**：`app.js` 里查询的每个 `#id`，是否都真实存在于 HTML 或由 JS 动态生成

第 2 项能拦住本项目 80% 的"点了没反应"。输出里有 ✗ 就必须先修，不要往下走。

### 第二层 · 流程驱动（约 1 分钟，每个迭代收尾必跑）

```bash
bash tools/verify.sh
```

它自动做：
1. 先跑第一层静态检查
2. 把应用**复制一份到 `/tmp`**（不碰交付物），注入 `tools/drive.js`
3. 用系统 Chrome 无头模式自动点击走完整个流程，逐阶段截图
4. 导出完成态的 DOM

产物在 `/tmp/zhiliao-verify/`。用图片查看器挑这几张看：

| 文件 | 看什么 |
|---|---|
| `s2.png` | 挂号单样式、进度轨是否推进 |
| `s3.png` | 病灶假设是否必须用户点选、确认按钮是否禁用态正确 |
| `s4.png` | 三档判定的高亮是否命中正确 |
| `s5.png` | 邀请函是否写了"为什么请他"、有没有引用对方内容 |
| `room-1180x820.png` | **会诊室在真实窗口尺寸下的布局**（最容易出问题的一张） |

|---|---|

| 行动清单有步骤 | ≥ 4 |

**病历闭环（5 项，v1.4 新增）** —— 数据层的端到端持久化

| 断言 | 阈值 |
|---|---|
| 行动清单带勾选框 | 含 `.rx-check` |
| 主流程出现回访日期 | 含 `.rx-review` 且带年份 |
| 勾选后切到病例页 | 含 `.rec-card` |
| **进度已写回档案** | 出现「2 / 4 已执行」 |
| 档案里有进度条 | 含 `.rec-prog-bar` |

> 这组的价值在于**它是端到端的**：勾选 → 写 localStorage → 切换视图 → 重新渲染 → 断言。
> 单元测试测不出这类问题（`localStorage` 的 bug 往往只在"读回来"的时候才暴露）。

**结案产出可以带走（4 项，v1.6 新增）**

| 断言 | 阈值 |
|---|---|
| 结论书带复制按钮 | 含 `btnCopyConcl` |
| 行动清单带复制按钮 | 含 `btnCopyPlan` |
| 已确诊分支也能复制 | 含 `btnCopySettled` |
| 信息不足分支能复制草稿 | 含 `btnCopyDraft` |

> 只能验证入口齐全 —— 剪贴板的实际效果需要真实剪贴板，无头环境断言不了，
> 这一条靠人工点一遍（见第七节「交付前最后一道关」）。

**真实 AI 的容错与诚实（5 项，v1.5 新增）** —— 接口不通时的表现

| 断言 | 阈值 |
|---|---|
| 接口不通时有可见的降级标注 | 含 `.src-tag.fallback` |
| **降级原因写在了界面上** | 出现「真实 AI 没能接通」 |
| 降级说明这是内置示例 | 出现「内置示例数据」 |
| **降级后流程没有卡死** | 仍能渲染出 `.triage` |
| 降级路径没有 JS 报错 | `<title>` 不以 `ERR:` 开头 |

> 这组测的是「接口接不通」这条路径。触发方式：把 Base URL 指向
> `https://127.0.0.1:1/v1`，连接会被立刻拒绝。
> **重点不是"有没有 try/catch"，而是"用户看不看得见"** —— 静默降级等于骗用户。

**判定真的驱动了分支（8 项，v1.5 新增）** —— 用「伪 AI」验证的核心一组

| 断言 | 阈值 |
|---|---|
| 有真实 AI 的来源标注 | 含 `.src-tag.live` |
| **判定跟随模型给出的结论** | 高亮的那一格是模型返回的判定 |
| 共识内容来自模型 | 出现模型返回的独有文本 |
| 行动清单也来自模型 | 出现模型返回的独有文本 |
| **确实改走了已确诊分支** | 合议消息数 **= 0** |
| **进度轨不含「会诊」** | 进度轨上只有 5 步 |
| 完成态已出现 | ≥ 1 |
| 没有 JS 报错 | `<title>` 不以 `ERR:` 开头 |

> 这组用一个**注入的假 `fetch`** 当"真实 AI"：它让争议检测返回 `current: 'settled'`，
> 而首页第一个示例靠关键词匹配本来会走会诊分支。**两者的判定故意不一致**，
> 如果流程还按关键词走，就会去开会诊 —— 断言就会抓到。
> 好处是：完全离线、不放任何真 Key，就能验证"判定真的改变了流程走向"。

**现场演示能力（7 项，v1.3 新增）** —— 路演前必须过的一组

| 断言 | 阈值 |
|---|---|
| 重置后回到初始态：输入框在 | ≥ 1 |
| **重置后没有残留文书卡** | **= 0** |
| **重置后没有完成态** | **= 0** |
| 重置后三个示例都在 | ≥ 3 |
| 自动演示能自己走完全流程 | 出现完成态 |
| 自动演示走的是会诊分支 | 会诊手记 ≥ 4 |
| 自动演示产出了结论书 | ≥ 1 |

> 加粗那几项是关键：它们校验的是**不该发生的事没有发生**。
> 例如「已确诊分支不能出现会诊消息」「重置后不能有残留卡片」——
> 这类否定式断言比正向断言更能抓到流程串线。
>
> **测「重置」时必须先走到流程中段再触发**。如果一上来就重置，页面本来就是空的，
> 断言必然通过，等于没测。驱动脚本的 T=30 就是先走到分歧地图再按 R。

**新增功能时，必须往 `tools/verify.sh` 里加对应的断言。** 只截图不数元素，等于没测。

## 四、回归矩阵（改了什么就必须连带测什么）

小项目最容易犯的错是"只测改的那一处"。按下表做最小回归：

| 本次改动了 | 必须连带回归 |
|---|---|
| `data.js` 的**顶层结构**（如案例组织方式、字段改名） | **三条分支都要走一遍**。结构改错会同时影响三条分支，且症状是「静默走错分支」而不是报错 |
| `pickCase()` 的匹配逻辑 | 逐个验证首页**三个示例**分别落到哪条分支，再加一个兜底输入（如「今天天气怎么样」） |
| `index.html` 的结构或 id | 第一层 id 核对 + **完整流程**（结构性改动影响面最大） |
| `css/app.css` 任意样式 | 会诊室（s6）+ 结论书（s8）截图，这两处组件最密 |
| `js/data.js` 的剧本数据 | 完整流程 + DOM 断言（数据字段缺失会静默变成空白） |
| `js/ai.js` | **演示模式**下完整流程必须仍然可用（默认路径不能坏）＋ 真实 AI 的降级路径（T=50） |
| `runMap()` 的判定逻辑 | T=51（伪 AI 判定与关键词预判不一致时，流程必须跟随判定） |
| 新增一个流程阶段 | 完整流程 + 新增阶段的前后衔接 + 进度轨 `RAIL` 是否对齐 |
| `localStorage` 相关 | 刷新后仍在 + 「清空我的病例」后重新挂号能跑通 |
| `app.js` 顶部的 `S` 状态字段 | 完整流程（状态字段漏初始化会一路静默失败） |

**回归范围判断原则**：拿不准就按"影响最大"的那一档做。

## 六、缺陷记录格式

发现缺陷时，不要只在脑子里记着。按这个格式写进当天的开发日志：

```
🐞 [待修 / 已修] 一句话描述
   现象：用户看到的是什么
   位置：文件 + 大致位置
   原因：为什么发生
   修法：怎么修的（已修时填）
   影响：会不会连累其他功能
```

**任何"静默失败"（页面没报错但功能不对）都要特别标记**，这类问题最危险。

## 七、交付前最后一道关

给用户看之前，**自己先用真实操作走一遍**（不要只依赖脚本）：

1. 双击 `知了诊所.app`，确认能打开
2. 用鼠标真实点完整个流程（脚本走的是预设路径，真人会点别的地方）
3. 试试"乱操作"：中途点浏览器刷新、连点两次按钮、把窗口拖到很窄
4. 确认没有卡死、没有空白、没有报错

第 3 步最关键——**评审不会按你预设的路径操作。**
