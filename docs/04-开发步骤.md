# 04 · 开发步骤与里程碑

> **核心原则：一次只做一个迭代。** 每个迭代的边界是"一句话能说清楚做完了什么"，
> 而且必须能被单独验证、单独回退。

---

## 一、七个不做（每次动手前默念一遍）

1. 不做当前迭代范围外的任何事（写进日志的「下一步候选」就行）
2. 不同时改多个模块
3. 不为"以后可能会用到"预留抽象
4. 不引入依赖
5. 不在没跑通的情况下说"做完了"
6. 不因为"顺便"而修改无关文件
7. 不动 `知了诊所-产品方案-终版.docx`

---

## 二、迭代节奏（固定动作，每次照做）

```
① 准备    读 CLAUDE.md → 读日志最近 3 条 → 读 04 确认范围 → 读 01/02/03 里相关的部分
② 动手    只改本次范围内的文件
③ 自测    跑 05 的三层验证（静态 / 流程 / 断言）
④ 写日志  往 00-开发日志.md 追加一条（用模板）
⑤ 更新    勾选本文件的检查项；本次若改变决策，同步 01/02/03
```

**迭代大小参考**：一次改动控制在 1 个模块、200 行以内。超了就是范围划大了，拆开。

## v1.1 · 会诊手记（供给端闭环）

**为什么先做这个**：这是方案第 6 节最薄的一环，也是评审最可能追问的点——
"创作者凭什么来？" 会诊手记是这个问题的唯一可视证据：**一次参与 = 一篇内容**。

**范围（做这些，别多）**
- 会诊结束、结论书发布后，为每位参与者生成一张《会诊手记》卡片
- 手记内容来自该参与者自己的证言 + 他在合议中的发言，不编造
- 卡片可预览，展示"这篇内容会挂在他的主页上"
- 在 `data.js` 里为 4 位专家各准备手记文案

**明确不做**
- ❌ 不做真实发布、不做创作者主页页面
- ❌ 不做手记的编辑与排版功能
- ❌ 不做分享导出

**DoD（v1.1 已完成）**
- [x] 会诊结束后能看到 4 张手记卡
- [x] 每张手记内容与该专家的证言一致（人工核对：陈默 8 个月 / 17 个 PR、苏晚 4000 份 / 60% / 8%、老周 31%、阿仓 132 份 / 4 家 / 3 家内推，均与其证言和合议发言一致）
- [x] 新增文案全部写进 `data.js`，`app.js` 不出现硬编码文案
- [x] 走查新增文书卡复用了 `docCard()`；折叠复用了 `.fold-head/.fold-body`；说明条复用了 `.notice.info`
- [x] 全流程回归通过（13 项 DOM 断言全绿）
- [x] 新增 3 项断言进 `tools/verify.sh`（手记数量 / 来源标注 / 可展开预览）
- [x] 新增驱动阶段 12：展开第一条手记并定位截图

**实施中的两个决策（记录在案）**
1. **会诊手记不进进度轨**。进度轨追踪的是「委托人自己的流程」，而手记是这场会诊的余波，不是他人流程的一步。加进去反而会让用户困惑"我在第几步"。
2. **手记不额外增加点击**。它是自动出现的卡片，主流程的 5 次点击预算没变。

**验收方式**：截图 4 张手记卡 + 驱动脚本跑到完成态做 DOM 断言（应有 4 个手记卡元素）

**明确不做**
- ❌ 不做真实检索与判定
- ❌ 不做"我想看不同意见"的后续会诊流程

**DoD（v1.2 已完成）**
- [x] 点不同的示例困惑，能走到不同的判定分支（三个示例 → 三档判定，已用脚本逐个验证）
- [x] 「已确诊」分支给出 3 条共识结论 + 每条带来源计数，并明确告诉用户不需要会诊
- [x] 「信息不足」分支给出可复制的提问草稿 + 4 条提问要点，把用户引导回知乎公开发问
- [x] 三档判定 UI 里当前命中项高亮正确（断言已加强为「校验被高亮的那一格」）
- [x] 全流程回归通过（三条分支分别断言，共 31 项）

**本次做成了三件事（原计划只有两件）**
1. **结构性改造**：`data.js` 从「单一 case」改成 `cases` 案例库 + `pickCase()` 按关键词选用。
   同时把 `verdicts` 提到全局、把「科室分诊」从按关键词改成案例自带，删掉了 `triage` 与 `triageOf`。
2. **已确诊分支**：直接给共识结论，不走会诊，产出《已确诊结论》。
3. **信息不足分支**：不给结论，改给一份可复制的《提问草稿》，把问题还给社区。

**实施中的关键决策**
1. **进度轨随分支变化**。分歧分支是 6 步（含「会诊」），非分歧分支是 5 步（不含）。
   否则会出现「会诊」这一步被标成已完成、但根本没发生过会诊的假象。
2. **两条非会诊分支的产出用同一套零件**：抽出 `planCardHTML` / `attachPlanCard` / `attachDoneCard`，
   三处共用，避免复制粘贴出三份会走样的卡片。
3. **`findings` 用 `findingRows()` 归一**。分歧 / 共识 / 零散讨论三种结构统一成同一套渲染，
   所以 `.dispute` 模板可以三档共用，没有新增一套 DOM。
4. **匹配打分改用「命中关键词的总字符数」**。一开始用命中个数，结果
   「AI 制药」同时命中了案例一的 `ai` 和案例三的 `海洋`+`制药`，票数打平、先定义的赢，
   第三个示例被错误地送进了会诊流程。改成按字符长度打分 + 收紧关键词后解决。

**验收方式**：`bash tools/verify.sh` —— 三条分支各走一遍并分别断言

## v1.3 · 演示稳定化

**为什么做**：路演是在别人电脑、别人网络下进行的。演示当场出问题的代价极高。

**范围**
- 一键重置：从任意状态回到初始态，1 秒内完成
- 演示快捷键：跳过等待、直接跳到某一阶段
- 录屏友好：提供一个"演示模式"，隐藏探索性元素（设置入口、帮助）
- 首次打开时的兜底提示

**明确不做**
- ❌ 不做真正的演示控制面板 UI
- ❌ 不做多案例切换界面（那是 v1.2 的事）

**DoD（v1.3 已完成）**
- [x] 从任意状态一键回到初始态，**无残留内容**（含掐断在途流程，见下方决策一）
- [x] 快捷键在别人电脑上可用（全单键，不依赖任何浏览器插件）
- [x] 演示模式下界面元素与正式版一致（只隐藏入口，不改变结构）
- [x] 全流程回归通过（新增 7 项断言，总计 36 项）

**范围调整说明**：原计划的第 2 条是「快捷键直接跳到某一阶段」。实施时改成了
**自动演示（P 键）**——因为「跳到第 N 阶段」需要另写一套构造中间状态的逻辑，
那套逻辑一旦和真实流程有出入，演示出来的就是假东西。
改成自动演示后，"跳到某阶段" = 快速播到那里，**复用同一套流程，不可能脱节**。

**实施中的关键决策**
1. **代次机制是这次真正的核心**。原来的「重置」只是清空界面——但上一次流程可能
   还在 `await` 里，醒来后会继续往**新页面**里塞卡片。修法是 `start()` 递增 `GEN`，
   `sleep()` 每次醒来检查自己出发时的代次，失效就抛 `ABORT`；所有流程入口用 `run()`
   包一层把 `ABORT` 静默吞掉。这一条不做，「无残留内容」就是句空话。
2. **取消首页输入框的自动聚焦**。焦点一旦落在输入框里，`P`/`R` 这些单键快捷键
   就会全部失效（否则打字会误触发）。演示时快捷键的可用性优先于"少点一次输入框"。
3. **自动演示只替用户点按钮，不重写流程**。这样它永远不会和真实流程脱节；
   完成态出现后自动收工，避免点「再挂一个号」造成无限循环。
4. **演示模式只隐藏入口，不改变结构**。接口上它和正式版是同一套界面 ——
   否则录屏看到的和现场演示的可能不一致。

**验收方式**：`bash tools/verify.sh` —— 新增「重置后无残留」与「自动演示能自己走完全程」两组断言

## v1.5 · 真实 AI 的正确性与容错 ✅

**为什么做**：做提交前的代码自查时，发现真实 AI 这条路上有三个问题，
其中最严重的一个会让产品最重要的承诺变成假话。**这三个问题在演示模式下都看不见**
—— 因为演示模式的 `verdict` 和 `map.current` 是天然一致的，正好把缺陷盖住了。

**范围**

1. **判定必须真的驱动分支**（R-20）。原来界面高亮的是 `map.current`（检测结果），
   决定走哪条分支的却是 `verdict`（挂号时用关键词猜的）。两者不一致时，
   界面上写着「已确诊、不必会诊」，流程转头就去请人开会诊了。
2. **降级必须让人看见**（R-21）。三处 AI 调用失败原来只写 `console.warn`，
   用户以为在看真实 AI 的结果，实际看的是内置示例。修复方式：
   `noteDegrade(步骤, err)` 记录 + `degradeNotice()` 贴到卡片上 + 每张推理卡带 `sourceTag()`。
3. **非会诊分支的内容也要来自本次推理**（R-22）。原来 `settled` 分支读
   `S.case.settled`、`insufficient` 分支读 `S.case.draft`，都是内置案例的数据。
   真实 AI 判定了「已确诊」，给的却是另一道题的共识结论 —— 判定是真的、内容是假的。
4. `chat()` 加 `AbortController` 超时（默认 90 秒），网络挂住时能自己断开。

**明确不做**
- ❌ 不做结案产出的复制 / 导出（列入 v1.6）
- ❌ 不改演示模式的任何分支逻辑（默认路径必须保持原样）
- ❌ 不引入任何依赖

**DoD（已完成）**
- [x] `disputes()` 一次调用产出三条分支各自需要的内容，判定与内容天然一致
- [x] `runMap()` 以 `map.current` 为准回写 `S.verdict` / `S.rail`，并重绘进度轨
- [x] 三处 AI 失败都有可见提示，且流程不中断、不出现空白卡片
- [x] 每张推理卡标注「真实 AI 推理 / 内置示例数据 / 已降级」
- [x] 接口不可达时，流程仍能用内置数据完整走完
- [x] 新增 13 项断言（含用「伪 AI」验证判定驱动分支的那一组），全流程回归通过

**实施中的关键决策**

1. **`disputes()` 改成一次给三组内容**，而不是判定一次、内容再一次。
   如果分两次拿，就可能出现「判定为已确诊、返回的却是分歧清单」的错位；
   一次产出，判定与内容不可能对不上。
2. **`if (out && out.disputes && out.disputes.length)` 是个隐藏的坑**。
   已确诊和信息不足这两种判定本来就没有分歧清单，用 `disputes.length` 当成功条件，
   会把它们全部误判成"调用失败"从而回退到内置案例 —— 判定永远生效不了。
   改成看 `out.current`。
3. **`S.note` 是写了但从未显示的字段**。上一版在 `runChart` 的 `catch` 里给它赋值，
   界面上却没有任何地方读它 —— 这就是「静默降级」的证据。本次直接删掉它，
   换成会渲染出来的 `S.degrades`。
4. **验证用「伪 AI」而不是真 Key**。T=51 阶段注入一个假的 `fetch`，
   让它在争议检测这步返回 `current: 'settled'`，而首页第一个示例靠关键词本来走会诊。
   这样能在完全离线、不放 Key 的前提下，证明「判定真的改变了流程走向」。

**回归**：`bash tools/verify.sh` —— 三条分支 + 演示能力 + 病历闭环 + 真实 AI 两条路径

**明确不做**

**DoD（已完成）**

**实施中的关键决策**
1. **实测跨域再动手**。先发 OPTIONS 预检确认 `access-control-allow-origin: *`，

4. **只接数据、没接 AI 时不假装做聚类**。如实列出检索到的原始讨论，
   并说明"判定仍来自内置示例"。**半真半假比全假更危险**。

## v1.9 · 手机适配 ✅

**为什么做**：给项目按官方四维度打分时，意识到**评委很可能用手机点开链接**。
实测 375px（iPhone 宽度）下：会诊室的标题被竖排成一列单字、顶栏品牌名折成两行、
首屏输入区的挂号按钮被挤出可视区。这种表现会直接被判「不可用」，而完成度占 25% 权重。

**范围**
- 新增 720px / 430px 两个断点，保留原有 860px
- 关键修复三处：
  - 输入区改纵向（提示语一行、挂号按钮全宽）—— 原来两者挤一行，窄屏下按钮被挤出
  - 会诊室头部改纵向（阶段指示器独占一行）—— 原来三个子项硬挤，中间被压到只剩一个字宽
  - 顶栏允许收缩但禁止折行（`white-space: nowrap`）
- 补上 flex 子项的 `min-width: 0`（默认 `auto` 会让长内容撑破容器）
- 新增 `?demo=1`：打开链接即自动播放演示，给评委用

**明确不做**
- ❌ **不改桌面端任何一行** —— 所有规则都包在媒体查询里
- ❌ 不做独立的移动端布局（同一套 DOM，只靠 CSS 适配）

**DoD（已完成）**
- [x] 375px 下首屏与会诊室均无横向溢出（自动检测）
- [x] 桌面端 1180px **像素级零差异**（新旧截图逐像素对比，差异区域为空）
- [x] 新增 3 项断言，含 iframe 窄屏检测
- [x] `?demo=1` 可用

**实施中的关键决策**

1. **踩到一个测试方法上的坑：Chrome 无头的最小视口是 500px**。
   直接开 375 的窗口会被静默提升到 500 —— 截出来的图其实是 500px 布局被裁到 375 宽，
   "按钮消失"是裁剪假象，不是真的溢出。**我差点据此做了错误的改造**。
   正确做法：**用 iframe 当容器**（iframe 内部 innerWidth 就是 375，媒体查询也按 375 生效）。
2. **宁可换行，不要硬挤**。会诊室头部的问题本质是 flex 不肯让步 ——
   子项默认 `min-width: auto`，内容多就撑破；而设了 `min-width: 0` 的那个又会被压到极限。
   解法不是调数值，而是让它们**换行**。
3. **验证方式**：在 375 宽度下量每个元素的 `getBoundingClientRect`，统计横向溢出数量，
   结果写进**父页面的 title**（`--dump-dom` 拿不到 iframe 内部的内容）供断言读取。

**回归**：`bash tools/verify.sh`（含手机检测）

## v1.12 · 专家门诊（商业化主路径） ✅

**对应方案 §11 商业化路径的第一条（专家门诊分成，优先级高）。**
方案原文把这条列为「保留，主路径」，但 48 小时范围里写的是「仅展示概念、不做实现」——

### 范围

| 做什么 | 说明 |
|---|---|
| 专家门诊视图 | 顶栏新增入口；免费/付费边界、号别定价、分成模型、可约号源 |

| 分成模型 | 平台 30% / 创作者 70%，明细逐项列出并给算例 |

### ★ 诚实底线（本功能最关键的一条）

**付款类功能，绝不能被伪装成真实扣款。** 因此：

- 视图顶部有显著的**演示声明**（黄色块）：专家为演示画像、挂号与付款均为演示流程、
  不产生真实扣款、不构成真实服务承诺
- 支付按钮的字面就是「确认挂号（**演示支付** ¥39）」
- 号单带**「演示号单」**橙色标记 + 二次声明「没有发生真实扣款，也没有真实专家接单」
- 专家与「会诊参与者」保持同一套口径：演示画像，不声称是真人

**为什么不做成「看起来很像真的」**：一个假支付界面出现在黑客松作品里，
评审的第一反应不是「做得真像」，而是「这家团队会不会在别的地方也不老实」。
标注清楚，反而显得可信——**它证明你分得清原型和产品**。

### 为什么不违背「不做专家门诊」的边界

方案 §13.2 写「不做专家门诊与声誉体系（仅展示概念）」，那是 **48 小时现场开发**的范围。
本次是赛后补做，把概念落成原型；**真实邀请通道与真实支付仍然不做**，
这一点在界面上明确写死。

### 验证

新增 24 项断言（`tools/verify.sh` 第「专家门诊 · 商业化」组），分三段驱动：
`#70` 列表 → `#71` 挂号面板 → `#72` 演示号单。覆盖视图渲染、边界文案、
演示声明（含「不产生真实扣款」这类**必须存在**的关键句）、分成展示、号单产出。
