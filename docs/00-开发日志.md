## 2026-09-13 ｜ v1.10+ ｜ 部署运维：自定义域名配置手册（应用本体版本不变）

**本次范围**：仓库外围的运维支持，**不是产品迭代**。不改应用本体任何代码，不动流程与文案。仅新增文档 + 调整仓库配置。

**做了什么**
- 新增 `知了诊所-域名配置手册.html`（仓库根目录）：把阿里云注册的域名绑到 Vercel 的逐步操作手册

  - 含 5 条报错现象 → 成因 → 修法的对照表
  - 做成"填一次域名、全文自动替换"的交互页，附一键复制
- `.vercelignore` 新增一条排除：否则手册会被部署成可公开访问的 `/知了诊所-域名配置手册.html`
- `CLAUDE.md` 目录地图登记该文件，并**补上了原本缺失的 `tools/` 一行**
- **装好阿里云 CLI**：`aliyun-cli v3.5.0`（arm64 官方二进制）→ `~/.local/bin/aliyun`
  - 没装 Homebrew（用户机器上没有，且为一个二进制装包管理器不划算），直接下 GitHub Release
  - `~/.local/bin` 本来就在 PATH 里（`.zshrc` 已有），**没有改动用户的 shell 配置**
- **新增 `tools/aliyun-dns-setup.sh`**：一条命令配完 DNS 并自动复核
  - **默认 dry-run**，只打印"要删哪条、要加哪条"，加 `--apply` 才写
  - 只用 `A` / `CNAME` 做冲突判定；**MX / TXT / NS 一律不碰**
  - 读 → 算 → 写 → **重新读服务端复核**（不按自己的意图报成功）
- 手册新增「方式二：让命令行替你配」（第 5 个步骤卡）

**为什么这么做**
- **凭据用 OAuth 而不是 AccessKey**：CLI v3.5 支持 `configure --mode OAuth`（官方标注 Recommended），
  浏览器登录授权、无需创建 AccessKey、不留长期密钥。AccessKey 等于账号全权限，
  让非技术用户"去 RAM 建子账号并最小授权"成本太高，OAuth 才是对的路
- **脚本必须只碰 A / CNAME**：`@` 上经常挂着邮箱的 MX 记录，`DeleteDomainRecord` 一旦误删，
  症状是"网站好好的，但收不到邮件"—— 这种故障极难排查。宁可少删，不可错删
- **默认 dry-run**：DNS 是线上服务的入口，误操作的影响面是整个域名。默认只读、显式 `--apply`，
  与项目里"验证是强制的"是同一条原则
- **用户给的 `dns31/dns32.hichina.com` 是阿里云默认 DNS 服务器地址，不是要填进某个框的记录值。**
  手册开篇必须先纠正这个认知 —— 否则用户会跑去改 nameserver，把一件 5 分钟的事做成两小时的事
- **CNAME 记录值选 `cname-china.vercel-dns.com`，而不是 Vercel 默认提示的 `cname.vercel-dns.com`**：
  前者是面向中国大陆的地址，能绕开 `*.vercel-dns.com` 常见的 DNS 污染。

6. **AccessSecret 不做后端中转**。跨域已开，纯静态直连即可；

**为什么这么做**

做提交前的代码自查，发现真实 AI 这条路有三个问题，**在演示模式下全都看不见**：

1. **判定与流程脱节（最严重）**。界面高亮的是 `map.current`（本次检测结果），
   决定走哪条分支的却是 `S.verdict`（挂号时用关键词猜的）。真实 AI 模式下这两者会不一致
   —— 界面上写着「已确诊、不必会诊」，流程转头就去请人开会诊了。
   这等于把 v1.2 建立起来的「产品会说不用会诊」变成一句假话。
2. **降级是静默的**。三处 AI 调用失败只写 `console.warn`，界面上毫无提示。
   用户以为在看真实 AI 的推理结果，实际看的是内置示例数据。
   路演时若被评委发现，整个产品的可信度就没了。
3. **非会诊分支内容错配**。AI 判定了「已确诊」，给出的却是内置案例里另一道题的共识结论。
   **判定是真的、内容是假的，比全假更糟** —— 因为它更不容易被发现。

关键决策与被否掉的方案：

- **`disputes()` 一次给三组内容**，而不是"先判定、再按判定取内容"。
  后者的隐患是判定与内容可能对不上；一次产出，结构上就不可能错位。
- **验证用"伪 AI"而不是真 Key**（T=51）。注入一个假的 `fetch`，让争议检测返回

- **否掉了"只在 console 里记降级"的方案**。理由是用户看不见就等于没说，
  这条也写进了 `docs/02` 的规矩里。

> 🐞 **[已修] 真实 AI 从来没有被调用过（静默失效）**
>    现象：设置里填了 Key、切到「接入真实 AI」、连「测试连接」都提示成功，

>         它比第一个更隐蔽——因为「测试连接」用的是裸标识符，是好的，

**为什么这么做**

- **代次机制才是这次的核心，不是"重置按钮"**。原来的重置只清空界面——但上一次流程可能还在 `await` 里，醒来后会继续往**新页面**里塞卡片。不做代次，DoD 里那句「无残留内容」就是空话。这是本轮最有价值的一处改动
- **为什么把「跳到某一阶段」改成「自动演示」**：跳阶段需要另写一套构造中间状态的逻辑，那套逻辑一旦和真实流程有出入，演示出来的就是假东西。自动演示只**替用户点按钮**，复用同一套流程，**不可能脱节**；"跳到第 N 阶段"就等于快速播到那里
- **取消首页输入框的自动聚焦**：焦点一旦落在输入框里，`P`/`R` 这些单键快捷键会全部失效（否则打字会误触发）。演示时快捷键的可用性优先于"少点一次输入框"
- **演示模式只隐藏入口、不改变结构**：录屏看到的必须和现场演示的是同一套界面

**验证情况**
- 静态检查通过（36 个 id）
- **16 个阶段截图 + 5 份 DOM 快照，38 项断言全绿**
- 新增的 7 项针对演示能力，其中 3 项是否定式断言：
  - 重置后**没有残留文书卡（=0）**、**没有完成态（=0）**
  - 自动演示能自己走完整个会诊分支、产出结论书与会诊手记
- 另外单独渲染确认了演示模式的外观：设置/帮助入口确实隐藏、右下角提示条正常

**遗留问题 / 下一步候选**
- 🐞 **本轮抓到一个真 bug，只在自动演示里暴露**：`pilotTick` 的点击判断只看了 `el.disabled`，而「跳过等待」按钮隐藏时用的是 CSS class 而不是 `disabled`。结果自动演示一直在"点"那个已经看不见的按钮，**在会诊室门口卡死**。已修：点击判断同时检查 `visible(el)`（`offsetParent !== null`）。这条已补进技能记录
- 自动演示目前固定走第一个示例（会诊分支）。要演示另外两条分支仍需手动点 → 记入「下一步候选」
- 快捷键没有做「冲突检测」：如果以后 Chrome 把某个单键占了，需要换键。目前 `P`/`R`/`空格` 在 file:// 下都正常
- 下一个迭代：**v1.4 病例档案增强**（行动清单可勾选进度、回访提醒可见）

- **被否掉的方案**：曾想让「信息不足」直接结束、不给行动清单。否掉了——信息不足时的第一条行动本来就是"去把信息拿回来"，给一份围绕"获取信息"而非"执行方案"的清单，逻辑更顺
