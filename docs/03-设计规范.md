# 03 · 设计规范

> 动任何界面或文案之前先看这里。**规范里已经定过的事，不要重新发明。**

---

## 一、五条设计原则（优先级从高到低）

1. **点击预算**：走完主流程不得超过 **5 次点击**。新增功能如果需要用户多点一次，必须先说明为什么值。
2. **层级上限**：全应用最多 **2 个主视图**（诊疗 / 我的病例）。子内容一律用浮层（overlay）叠加，**不开新页面**。
3. **永不出现"返回"**：页面是一条向下的流，用户永远知道自己在哪一步。如果需要"返回"，说明设计错了。
4. **零输入也能通过**：每个需要用户表达的环节都要提供快捷选项。不能假设用户愿意打字。
5. **说人话**：不使用内部术语、不堆缩写。界面上的每个词，一个没学过产品的大学生都应该看得懂。

|---|---|---|

**三档判定的色彩语义（v1.2 起固定，不要改）**

| 档位 | 程度条 | 提示条 | 含义 |
|---|---|---|---|
| 存在真实分歧 | `.level.hi` 红 / `.level.mid` 琥珀 | `.notice.warn` 琥珀 | 检出对立观点簇，**要会诊** |
| 已确诊 | `.level.ok` 绿 | `.notice.ok` 绿 | 早有共识，**不必会诊** |

> ⚠️ 语义色一旦用在别处，用户就失去了判断状态的线索。**不允许**用它们做纯装饰。

### 会诊参与者配色

`data.js` 里每位专家自带 `color`，按固定顺序取用，保证同一人在整场会诊里颜色一致：

`#0084FF` → `#F1403C` → `#FF9607` → `#0F6E56` → `#7F77DD` → `#D4537E`

## 三、字体

字体栈（固定，不改）：

```
-apple-system, BlinkMacSystemFont, "PingFang SC", "Hiragino Sans GB", "Microsoft YaHei", sans-serif
```

等宽字体（仅用于挂号单等"单据"类文书）：`"SF Mono", "Menlo", monospace`

### 字号阶

| 场景 | 字号 | 字重 | 行高 |
|---|---|---|---|
| 页面主标题（如结论书标题） | 19px | 600 | 1.5 |
| 卡片标题 | 15px | 600 | — |
| 正文 / 对话气泡 | 14–14.5px | 400 | 1.7–1.8 |
| 次要说明 | 13.5px | 400 | 1.7 |
| 元信息 / 标签 | 12–12.5px | 400 / 500 | 1.6 |
| 极小标签（进度轨） | 11px | 400 | — |

**最小字号 11px，不得更小。** 字重只用 400 和 500/600，不用 700+。

### 响应式约定（v1.9）

断点三个：**860px**（会诊室隐藏侧栏）／**720px**（平板及以下，主要适配层）／**430px**（手机）。

两条铁律：

1. **所有响应式规则必须写在 `@media` 里**，桌面端（>720px）一行都不许改。
   每次改完用「新旧截图逐像素对比」确认差异为零。
2. **flex 子项默认 `min-width: auto`，长内容会撑破容器** —— 该收缩的容器一律显式
   `min-width: 0`；但更根本的解法是**允许换行**（`flex-wrap: wrap`），而不是压缩子项。

> ⚠️ **测手机宽度不能用 `--window-size`**：Chrome 无头模式的最小视口是 **500px**，
> 开 375 会被静默提升到 500，截出来的是"500px 布局裁到 375 宽"的假象。
> 正确做法是**用 iframe 当容器**，见 `tools/verify.sh` 里的手机检测段。
| 会诊手记 | `.hn` + `.hn-head/.hn-title/.hn-src/.hn-meta/.hn-excerpt` | 供给端的产出（v1.1 新增） | 必须标注「整理自哪几处」与「未新增任何事实」；`.hn-meta` 最后一栏用主色强调 |
| 提示条 | `.notice.{info\|warn\|ok}` | 说明与警示 | 信息用蓝，提醒用黄，已确诊用绿 |
| 折叠 | `.fold-head` + `.fold-body` | 展开更多细节 | 默认收起 |
| 启动兜底 | `.boot` | 脚本没起来时的提示层 | 启动成功后**必须移除**，不能常驻 |
| 演示提示条 | `.demo-hint` | 演示模式下右下角的快捷键提示 | 位置固定在右下角，`pilot-on` 时状态点变绿；只在演示模式出现 |
| 开关行 | `.switch-row` | 设置里的复选框 + 说明文字 | 标签整体可点，别只让复选框可点 |

## 五之二、现场演示的交互约定（v1.3 起）

演示场景和日常使用是两套完全不同的约束，单独约定：

| 项 | 约定 | 理由 |
|---|---|---|
| 快捷键 | `P` 自动演示 / `空格` 暂停或跳过 / `R` 重置 / `Esc` 关浮层 | 全用单键，不依赖浏览器插件，在别人电脑上也能用 |
| 输入框里不触发 | 焦点在 `input`/`textarea` 时，单键快捷键一律不响应 | 否则打字会误触发重置 |
| **不自动聚焦输入框** | 首页打开后焦点留在 body，不落在输入框 | 焦点一旦在输入框里，演示快捷键就全被挡掉。演示时快捷键的可用性优先于少点一次 |
| 演示模式 | 只隐藏「设置」「帮助」入口 | **界面结构与正式版完全一致**。演示模式不允许是"另一套界面"，否则录屏和实际演示会对不上 |
| 自动演示的本质 | 它只是**替用户点按钮**，不重写流程 | 这样它永远不会和真实流程脱节。任何"跳过流程直接摆出结果"的实现都是在骗自己 |
| 重置的语义 | 掐断所有在途流程 + 清空界面 + 回到初始态 | 只清界面不掐流程，旧流程会继续往新页面塞卡片 —— 这是最容易被忽略的一类 bug |

## 六、动画

| 场景 | 规格 |
|---|---|
| 卡片入场 | `rise`：上移 12px + 淡入，420ms，`cubic-bezier(.2,.8,.3,1)` |
| 消息出现 | `fade`：淡入 500ms |
| 弹窗 | 遮罩淡入 200ms + 容器 300ms 上浮 |

## 七、文案规范

### 7.1 狐看山医生的口吻

| 该这样 | 不该这样 |
|---|---|
| 短句，一次说一件事 | 大段书面语 |
| 有判断，直接说"我建议" | 含糊的"可能""也许" |
| 生活化比喻（"别再看第 201 个回答"） | 行业黑话、英文缩写 |
| 承认自己不确定（"这只是我的猜测，不算数"） | 装作全知 |

**核心人设**：他不是给你答案的人，是替你张罗事的人。所以他会说"我去请人""我去翻一遍"。

### 7.2 禁用词

| 禁用 | 换成 | 原因 |
|---|---|---|
| 患者、病人 | **委托人** | 用户不是来看病的，是来提病例的 |
| 化验单 | **分歧地图** | 原名要用户自己理解映射关系 |
| 诊断书 | **会诊结论书** | 避免"医生对病人下判断"的压迫感 |
| 处方笺、开药 | **行动清单** | 与"AI 不开药"自相矛盾 |
| MDT | **会诊** | 缩写念出来会绊住 |
| 知了大夫、猫医生 | **狐看山医生** | 历史上出现过三个称谓，已统一 |

### 7.3 术语统一表（全项目唯一写法）

| 概念 | 唯一写法 | 备注 |
|---|---|---|
| 主诊医生 | **狐看山医生** | 全文唯一称谓，不得出现任何其他版本（含自称、提示词、说明文案） |
| 人物形象 | **`assets/fox-avatar.png`**（头像）/ **`assets/fox-doctor.png`**（全身插画） | 白大褂 + 听诊器 + 医疗箱的狐医生，浅蓝底 |
| 产品名 | **知了诊所** | 「知了」双关：蝉 / 知道了 |
| 用户 | **委托人** | 官方称谓 |
| 核心动作 | **会诊** | — |
| 三份文书 | **分歧地图 / 会诊结论书 / 行动清单** | — |
| Slogan | **你的问题，挂号了。** | 备选：你的问题，值得一次会诊 |

> ⚠️ 全项目曾经同时出现「狐看山医生 / 知了大夫 / 猫医生」三种称谓，是路演现场最容易露怯的地方。
> 改文案时**必须**照着 7.3 这张表来。

### 7.4 人物形象的使用规则（v1.3.1 起）

**全项目只有一个"人物"是狐看山医生。** 其余出现在会诊里的参与者是**不同的真人**，
必须保持彼此可区分。

| 出现位置 | 用什么 | 为什么 |
|---|---|---|
| 顶栏品牌标记 | `fox-avatar.png` | 品牌形象 |
| 医生对话气泡 / 打字中气泡 | `fox-avatar.png` | 说话人标识 |
| 会诊室主持人消息 | `fox-avatar.png`（`.msg-av-host`） | 主持人是狐看山医生 |
| 会诊室参与者消息 | **各自颜色的字母头像** | 他们是四位不同的专家，**不能换成同一个头像** |
| 会诊邀请函的专家行 | **各自颜色的字母头像** | 同上 |
| 会诊手记的作者 | **各自颜色的字母头像** | 同上 |
| 启动兜底层 / 帮助弹窗 | `fox-avatar.png` / `fox-doctor.png` | 人物登场处 |
| 应用图标 | `fox-doctor.png`（macOS 圆角） | 见 `知了诊所.app` |

**红线**：不要把四位会诊专家的头像也换成狐看山医生。
一旦换掉，"四个不同的人坐在一起讨论"这件事就消失了——而这是整个产品的地基。

**头像裁切要求**：必须在**头部特写**（含双耳、五官完整）上切圆。
按实测，`(200, 10, 690, 500)` 是最佳裁切——在 24px 上仍能辨认出脸。
