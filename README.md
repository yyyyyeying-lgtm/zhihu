# 知了诊所

> 把一个人的困惑当作一例病例，让 AI 组织一次真实的会诊，
> 产出一份公开的《会诊结论书》和一份私密的《行动清单》。

**知乎黑客松 2026 · 校园新锐季 ｜ 赛道：知识炼金场**

---

## 这是什么

知乎不缺答案——平台上累计内容 9.5 亿条。但一个 23 岁的应届生打开「我该不该转行」时，
看到的是一千个互相矛盾的答案，**没有一个是「在他这个处境下」的结论**。

知了诊所做的是这个「收敛」动作：

```
  说困惑  →  挂号  →  问诊  →  确认病灶  →  看判定  →  拿结论
                                    ↓
                        ┌───────────┴───────────┐
                        │  三档判定（关键机制）    │
                        └───────────┬───────────┘
                                    ↓
        已确诊 ──────→ 直接给共识结论，不请人
        存在真实分歧 ─→ 组织会诊：异步证言 → 同步合议 → 结论书
        信息不足 ────→ 不给结论，给一份可复制的提问草稿，交还社区
```

**AI 不上台答题，AI 负责把对的人请到一张桌子上。**

### 部署

**导入即用，无需任何配置。** 应用本体就在仓库根目录，而所有静态托管平台都遵循
「从根目录提供文件」这个约定 —— 打开 Vercel / Netlify / Cloudflare Pages，
直接 Import 本仓库即可，不需要填 Root Directory。

仓库里已备好两个部署配置文件：

| 文件 | 作用 |
|---|---|
| `vercel.json` | 显式声明这是纯静态站点，开启 `cleanUrls`（访问 `/index.html` 会跳到 `/`） |
| `.vercelignore` | 只部署应用本体（8 个文件 / **364KB**），工程文档、参赛材料、`.app` 启动包都不上传 |

> ⚠️ **如果你的 Vercel 项目是之前建的、现在还报 404**：
> 去 `Settings → Root Directory` 确认那里是**空的**。这个设置会覆盖仓库的实际结构 ——
> 之前应用在子目录时可能被手动设过，不清空的话，仓库改对了也不会生效。
> 最省事的做法是**删掉该项目重新 Import 一次**。

## 技术特点

**纯静态网页应用，零依赖、零构建。** 源码即产物。

| | |
|---|---|
| 文件数 | 8 个（1 个 HTML + 1 个 CSS + 4 个 JS + 2 张图） |
| 代码量 | 约 4,100 行 |
| 第三方库 | **0 个**（包括 CDN 引入也为 0） |
| 构建步骤 | **无** |
| 后端 | **无**（可直接部署到任意静态托管） |
| 数据存储 | 全部在浏览器 `localStorage`，不上传 |

### 三个可选的外部能力（都不配也能完整跑通）

| 能力 | 说明 |
|---|---|
| **知乎数据开放平台** | 配置 AccessSecret 后，分歧地图检索**真实站内讨论**（含赞同数、作者、权威等级）。接口已开跨域，纯静态可直连 |
| **真实大模型** | 支持任意 OpenAI 兼容接口（DeepSeek / 智谱 / Kimi / 通义 / OpenAI）。不配则走内置演示剧本 |
| **全部不配** | 内置演示剧本，开箱即用——这也是路演时最稳的模式 |

每张推理卡都会标注**数据来源**：`真实 AI 推理` / `内置示例数据` / `已降级`。
**降级一定写明原因，不会静默换成示例数据。**

## 工程质量：可自动验证

```
bash tools/verify.sh
```

一条命令跑完：静态检查 + 21 个阶段自动截图 + **81 项 DOM 断言**（11 组）。

用系统 Chrome 无头模式驱动，不需要 playwright / puppeteer，**不需要装任何 npm 包**。

断言覆盖：

| 组 | 验什么 |
|---|---|
| 分支一 · 存在真实分歧 | 完整会诊：证言、合议、来源计数、少数意见、共同署名 |
| 分支二 · 已确诊 | 给出共识结论，且**合议消息数 = 0**（确实没开会诊） |
| 分支三 · 信息不足 | 给出提问草稿与要点，且**没走会诊** |
| 病历闭环 | 勾选进度 → 切换视图 → **进度已写回档案**（端到端持久化） |
| 真实 AI 容错 | 接口不通时降级**可见**、流程不卡死 |
| 判定驱动分支 | 用注入的假 `fetch` 让判定与关键词预判故意不一致，验证流程跟随判定 |
| 产出可带走 | 三处结案产出的复制入口 |
| 知乎数据源 | 只接数据 / 数据 + AI 两条路径 |
| 形象与称谓统一 | 全项目只有一个形象、一个称谓 |
| 手机适配 | 375px 下首屏与会诊室**零横向溢出** |

其中最有价值的是**否定式断言**——比如「已确诊分支不能出现会诊消息」。
这类断言比正向断言更能抓到流程串线。

> 这套验证不是摆设：它在开发过程中抓到过多个**页面看起来正常、功能其实没跑**的缺陷，
> 详见 `docs/00-开发日志.md`。

## 已知限制

产品在开发中始终坚持「不假装比实际更真」，以下为本期实现范围与产品化路径：

- **知乎真实检索已接入**：分歧地图跑在 `developer.zhihu.com` 数据开放平台的站内检索 API 上
  （Bearer 鉴权 + `X-Request-Timestamp` 时间戳），含额度处理。未配置 AccessSecret 时
  回落到离线语料快照，界面标注数据来源，两种来源不混淆。
- **会诊参与者的证言与合议，由 AI 依据知乎真实讨论编排**。检索、三档判定、会诊编排、
  文书生成全链路真跑；本轮 Demo 不含真实邀请通道 —— 产品化阶段接入站内通知后，
  即为真实创作者的异步证言。
- **产出带回已打通**：结论书与行动清单都支持「一键复制 Markdown」，可直接带回知乎发布；
  自动发布通道待平台授权后接入。
- **无需登录即可完整体验**；登录与知乎 OAuth 在规划内。
- **「信息不足」分支的行动清单**当前用通用内容（「先把信息拿回来」），该内容普适、不依赖具体问题。
- **专家声誉体系、机构号、订阅制**属产品化规划，本期未实现。

完整清单见 `docs/05-测试与验收.md` 第五节。
