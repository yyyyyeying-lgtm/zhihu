把你在阿里云买的域名，指到 Vercel 上的知了诊所

照着从上往下做，四步。全程不需要写代码，也不需要改 DNS 服务器。

目标平台：Vercel ｜ 域名解析：阿里云云解析 DNS ｜ 更新：2026-09-13

只填域名本身，不要带 https://、不要带 www.、不要带结尾的斜杠。填不对后面就是白做，所以先填这里。

🚧 前置条件：阿里云账号必须先完成「账号实名认证」

阿里云官方规定（依据《反电信网络诈骗法》，2024-01-23 起生效）：未完成账号实名认证的阿里云账号，无法新增或修改域名解析记录。

这一条网页控制台和 API 都会被拒，换 AccessKey、换授权方式都绕不过去。报错是 Identity.Uncertified。

注意：「域名实名认证」和「账号实名认证」是两件事 —— 域名认证过了也没用，卡的是账号。

解决：阿里云控制台 → 账号中心 → 实名认证。个人认证走支付宝通常秒过，完成后回来继续。

排查方法：yeing.online 在 dns31/dns32.hichina.com 上一条 A/CNAME 记录都没有，就是这个限制的直接结果。

你给我的 dns31.hichina.com / dns32.hichina.com，是阿里云默认的 DNS 服务器地址。

它不代表任何要填进输入框的记录值，只说明一件事：你这个域名的解析权在阿里云。所以你哪儿都不用搬家，直接去阿里云「云解析 DNS」加两条记录就行。

同理，不要去 Vercel 选「把 DNS 交给 Vercel 托管（Nameservers）」，那会把你的域名服务器改掉，多一个出错环节，没有任何好处。

1

在 Vercel 里把域名加进去 Vercel 控制台 → 你的项目 → 顶部 Settings → 左侧 Domains

  1. 在 Add Domain 输入框里填 www.{{DOMAIN}}，点 Add。
  2. 再加一次，这次填 {{DOMAIN}}（不带 www 的根域名），点 Add。
  3. 加完两个后，Vercel 会问你哪个是主域名。选 www 为主域名，让根域名 301 跳转到 www。

为什么先加 www？因为只有子域名能用 CNAME 记录，而 CNAME 才是国内访问最稳的那一种。根域名只能用 A 记录，路由更死板。

这一步会显示红色报错，是正常的

加完域名，Vercel 会显示 Invalid Configuration，并且列出它要你配置的 DNS 记录值。这一步的报错不用管，做完第 2 步它自己会变绿。

但请把那张域名卡片上的两个值抄下来或截图，尤其是 A 记录的 IP —— 它是你这一个项目专属的，别人的教程里的值不一定是你的。

2

在阿里云云解析 DNS 添加两条记录 阿里云控制台 → 搜索「云解析 DNS」→ 域名列表 → 你域名右侧的「解析设置」→ 添加记录

一共加三条（A 记录要两条）。字段对照如下，照着填：

记录类型主机记录记录值TTL说明
CNAME www 1ef7e654b609fb83.vercel-dns-017.com 10 分钟 项目专属值，必加
A @ 216.198.79.1 10 分钟 两条都要加，Vercel 按项目分配，缺一条验证不过
A @ 64.29.17.1 10 分钟
不用加：AAAA（IPv6）、CAA、以及任何一条 Vercel 没要求的记录。IPv6 记录会干扰 Vercel 签证书。
这三个值是怎么来的？别抄教程

它们来自你在 Vercel 上的真实项目，不是通用值：

vercel domains verify yeing.online
vercel domains verify www.yeing.online

网上教程普遍写的 76.76.21.21 和 cname.vercel-dns.com 对这个项目是错的 —— 实测本项目的 A 记录是 216.198.79.1 和 64.29.17.1，CNAME 目标也是一串项目专属哈希。 用通用值会导致 Vercel 永远停在 Invalid Configuration。

这条 CNAME 的值可以直接复制：

1ef7e654b609fb83.vercel-dns-017.com
加之前，先把冲突的旧记录删掉

如果主机记录 www 或 @ 上已经有别的 A / CNAME 记录（阿里云买域名后常会自带一条停放页记录），先删掉再新增。新旧记录并存会导致流量随机分流，Vercel 会一直验证不过。

主机记录只填前缀，不要填完整域名

加 www 时，主机记录填 www，不要填 www.{{DOMAIN}}。加根域名时填 @，不要留空、不要填域名本身。

3

回 Vercel 等它变绿 Vercel → Settings → Domains

  1. 回到 Domains 页面，如果状态还没更新，点一下域名卡片上的 Refresh。
  2. 等 1 到 10 分钟。两个域名都显示绿色对勾、Valid Configuration，就成功了。
  3. Vercel 会自动签发 HTTPS 证书，不用你操作。证书签发通常再等几分钟。

变绿之后，你的站点地址就是 https://www.{{DOMAIN}}。

4

验证真的通了 浏览器 + 一个查解析的网站

  1. 浏览器打开 https://www.{{DOMAIN}}，确认地址栏有小锁、页面正常。
  2. 打开 https://{{DOMAIN}}，确认它会自动跳到带 www 的地址。
  3. 用手机 4G／5G 流量（关掉 Wi-Fi）再打开一次 —— 这一步最关键，评委多半就是这么点开的。

想知道解析到底生效没有，去 dnschecker.org，输入 www.{{DOMAIN}}，看世界各地是否都解析到 Vercel 的 IP。中国节点显示的结果，基本就是你国内用户会遇到的实际情况。

方式二：让命令行替你配（推荐）
CLI

不用手点控制台，一条命令配完并自动复核 已装好：aliyun CLI v3.5.0 → ~/.local/bin/aliyun

仓库里已经备好脚本 tools/aliyun-dns-setup.sh。它会先读一遍你域名上现有的记录、 算出「要删哪条、要加哪条」，再动手，最后重新读一遍服务端做复核。

为什么值得用这条：它能替你处理最容易出事的一步 —— 清理旧记录。 阿里云买域名后常自带停放页记录，多条 A 记录并存会让 Vercel 验证永远不通过。 而这个脚本只清理 A 和 CNAME，绝不碰 MX、TXT、NS（@ 上常有邮箱记录，误删就收不到邮件）。

默认只看不写，确认无误才加 --apply：

bash tools/aliyun-dns-setup.sh yeing.online --apex-ip 216.198.79.1 --apex-ip 64.29.17.1
bash tools/aliyun-dns-setup.sh yeing.online --apex-ip 216.198.79.1 --apex-ip 64.29.17.1 --apply
用这条之前，先授权一次

命令行要能代表你的账号操作，必须先授权。推荐用 OAuth 扫码登录（官方推荐方式）， 不用创建 AccessKey、不留长期密钥：

aliyun configure --profile zhihu --mode OAuth

跑完会打开浏览器让你登录阿里云并确认授权。授权后凭据只存在本机，随时可以用 aliyun configure delete --profile zhihu 撤销。

已用假凭证测过，不会误删

三种场景都验过：① 混着 MX / TXT / 冲突 A 记录时，只删该删的两条，邮箱记录毫发无损； ② 只有一条过时 A 记录时，删旧加新；③ 已经配好时，零改动，不会重复添加。

必须提前知道的一个风险
Vercel 在中国大陆没有节点，国内访问不保证通

这不是你配错了，是 Vercel 的固有限制：它在中国大陆没有服务器和 CDN 节点，官方也明确说不保证大陆地区的可用性。

网上流传的「国内优化 CNAME」（cname-china.vercel-dns.com）是民间偏方： 它确实能绕开一部分 DNS 污染，但 Vercel 的域名验证是按项目专属目标校验的， 换成偏方值很可能永远验证不过。先用 Vercel 指定的值跑通，再谈优化。

所以给你的实际建议：这个比赛面向国内评委，别把希望全押在域名上。提交时把两个地址都给出去 —— 主推域名，同时附上那个手机能直接打开的演示链接作为兜底。评委点哪个都能看到东西。

真要彻底解决，只有换国内节点托管（阿里云 OSS + CDN），但那个必须走 ICP 备案，周期以周计，现在来不及。

好消息：不需要备案

备案只管「服务器在中国大陆境内」的情况。Vercel 在境外，所以你现在这条路不需要 ICP 备案，买完域名就能配。前提是域名本身完成了实名认证（阿里云新域名一般已经自动完成，没完成的话控制台会提示）。

报错对照表
你看到的现象真正的原因怎么修
Vercel 一直 Invalid Configuration 旧记录没删，或记录值填错 回到第 2 步，删掉 www / @ 上的其他 A、CNAME 记录，只留手册里这两条
解析查得到，但浏览器打不开 刚改完，还没到生效时间 等 10 分钟再试；阿里云 TTL 最短就是 10 分钟，急不来
能打开但提示「不安全」 证书还在签发 再等几分钟；仍不行就在 Vercel 里把域名删掉重新 Add 一次
国内打不开，挂梯子就正常 大陆网络对 Vercel 的限制 没有一键解决方案。先确认记录值用的是 Vercel 指定的（见第 2 步），然后用兜底链接
域名被暂停 / serverHold 阿里云域名没做实名认证 去阿里云域名控制台完成实名认证，认证过后解析才会通
三件不要做的事
  • 不要改 DNS 服务器。dns31 / dns32 保持原样。换成 Vercel 的 nameserver 只会让流程更长、更易出错。
  • 不要抄网上的「Vercel 国内优化 IP」。那些 IP（比如 76.227.x.x 之类）来源不明，Vercel 验证要求记录值和你的域名卡片完全一致，抄错的直接判不通过。
  • 不要为了加速去套 Cloudflare 再开橙色云朵。橙云会隐藏真实解析，Vercel 验证期一定失败。这条路要配也得先用灰云验证通过再说，不值得现在折腾。
